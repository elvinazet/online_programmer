## MVP

### Этап 2 — Скелет бэкенда + авторизация ✅

- FastAPI-приложение, конфиг, подключение PostgreSQL (SQLAlchemy + Alembic).
- Docker Compose: `api`, `db`, `redis` (базовый набор).
- Модели/миграции домена «Пользователи, аутентификация, группы».
- Auth: регистрация, подтверждение email, вход (JWT access+refresh, ротация),
  восстановление пароля, RBAC (ученик/учитель), профили.

**Тестируем:** регистрация → письмо-подтверждение → вход → доступ к защищённому
эндпоинту по роли → refresh → сброс пароля.

### Этап 3 — Учебники + фронтенд-скелет ✅

- Модели/миграции домена «Учебники и прогресс».
- API: курсы/уровни/модули/уроки (чтение для учеников, CRUD для учителей),
  мини-квизы, отметка прохождения урока, прогресс.
- Админ-панель учителя: Markdown-редактор урока с превью.
- Frontend: каркас Next.js (App Router, Tailwind), страницы auth, читалка
  уроков с подсветкой кода, запуск встроенных примеров в браузере (Monaco),
  прохождение мини-квиза.

**Тестируем:** учитель создаёт урок → ученик читает, запускает пример, проходит
квиз → урок отмечается пройденным → виден прогресс.

### Этап 4 — Codeforces + локальная проверка кода ✅

- Модели/миграции домена «Задачи, Codeforces, сабмиты».
- Клиент CF с rate-limit (token-bucket в Redis, 1 req/2s); кэш
  `problemset.problems`; фильтрация/подбор по тегам и рейтингу.
- Привязка Codeforces-хэндла; Celery beat + worker: опрос `user.status`,
  автопометка решённых задач, streak.
- **Judge:** Monaco-редактор → sandbox (Docker, `net=none`, лимиты CPU/mem,
  без доступа к ФС хоста) → прогон на тестах → вердикт (C++ и Python).
- Дашборд прогресса: график решённого по времени, распределение по
  тегам/сложности, слабые темы.

**Тестируем:** привязка хэндла → подбор задач под уровень → отправка решения →
корректные вердикты (AC/WA/TLE/RE/CE) → изоляция sandbox (нет сети/ФС) →
решённое на CF подтягивается в платформу.

**Веха: конец MVP ✅** — авторизация, учебники, задачи Codeforces с локальным
тестированием работают end-to-end.

> Примечание: judge через Docker (`DockerExecutor`) собран, но проверялся
> логикой/тестами на `LocalExecutor`. Реальную изоляцию контейнеров нужно
> прогнать в среде с Docker (`docker compose up` + `bash backend/sandbox/build.sh`).

## Полная версия

### Этап 5 — Экзаменационная система ⬜

- Модели/миграции домена «Экзамены».
- Конструктор экзаменов для учителя: выбор задач и правил выборки теор-вопросов
  из банка модулей, настройка времени и порога.
- Прохождение: серверный таймер (`ends_at`), материализация варианта попытки
  (рандомизация вопросов/вариантов, разные задачи у разных учеников),
  практика через sandbox с частичными баллами, теория из банка.
- Подсчёт баллов и порога, автозавершение по времени с сохранением ответов,
  пересдача через N дней, базовый античит (фиксация потери фокуса).
- Открытие следующего уровня после сдачи (`student_level_access`).

**Тестируем:** конструктор → старт попытки → таймер и автосабмит на сервере →
подсчёт практики+теории → порог/провал → блокировка пересдачи на N дней →
разные варианты у двух учеников.

### Этап 6 — Разбор результатов и планы подготовки ⬜

- Разбор попытки по темам (`attempt_topic_results`): карта сильных/слабых тем
  (тепловая карта), привязка каждого пункта к модулю.
- Прямые ссылки на уроки по проваленным темам; автогенерация персонального
  плана подготовки (уроки + тренировочные задачи CF по слабым тегам/рейтингу).
- История экзаменов в профиле: динамика по темам между попытками.
- Учитель: те же разборы по каждому ученику + агрегат по группе (какие темы
  западают у группы).

**Тестируем:** после сдачи/провала виден разбор по темам → ссылки ведут на
нужные уроки → план подготовки релевантен слабым темам → учитель видит агрегат
по группе → динамика между попытками.

### Этап 7 — Харденинг и продакшн-готовность ⬜

- Rate-limiting API, логирование/метрики, обработка ошибок.
- Усиление безопасности sandbox (seccomp, лимиты вывода, аудит).
- Тесты (unit/integration), сиды демо-данных, CI.
- `nginx` + TLS, финальный `docker-compose` для деплоя.

**Тестируем:** нагрузочные проверки judge, negative-тесты безопасности,
проход CI, чистый деплой «с нуля».
